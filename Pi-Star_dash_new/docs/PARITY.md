# Что сохранено из Pi-Star Dashboard

**Полный интерфейс оператора и администратора реализован в PHP.** В варианте с новой темой за формы, обработку команд, обновление таблиц и доступ к системе отвечает исходный PHP-код Pi-Star. Новое оформление или ссылка из Svelte на `/admin/configure.php` не означают, что настройки перенесены на Svelte или работают на обычной Raspberry Pi OS.

Эталон для сверки — локальный клон [`Pi-Star_DV_Dash`](../../Pi-Star_DV_Dash), коммит `10bf34c902517e8d8c7694794b79b0dd80cfebe2`, версия Dashboard `20261121`. Ниже указаны пути **от корня сайта эталона**. Инвентаризация выполнена по исходникам, без запросов к узлам, внешним сетям и модемам. Наличие обработчика в клоне не подтверждает выполнение операции на конкретной плате.

## Dashboard: что меняется с режимом и правами

`/index.php` и `/admin/index.php` — один файл (второй путь — символьная ссылка). На `/` выводятся сведения для наблюдения и ссылки на вход/настройку. Вывод управляющих форм зависит от **точного** `PHP_SELF == "/admin/index.php"`. Режим определяется сначала по `/etc/dstar-radio.mmdvmhost`, затем по `/etc/dstar-radio.dstarrepeater`. Если нет обоих маркеров, появляется **No Mode Defined** и через 10 с браузер переходит к `/admin/configure.php`.

В шапке — имя узла, позывной шлюза, версии Pi-Star и Dashboard, настраиваемый баннер; внизу — ссылки на поддержку и дистрибутив. Общие зависимости: `config/{version,language,ircddblocal,browserdetect}.php`, `lang/`, `/etc/pistar-release`, `/etc/pistar-css.ini`, полная и компактная темы `css/pistar-css.php` и `css/pistar-css-mini.php`. На страницах с длинными списками используется поиск NiceSelect. Административные предупреждения об устаревшем выпуске, DMR без списка доступа, старом BM-ключе или заводском пароле не должны появляться на публичном экране.

## API и границы серверной части

**`GET /api/last_heard.php?num_transmissions=N`** — лента последних передач MMDVMHost, новые первыми. JSON-массив, не объект со статусом. Без параметра берётся вся доступная в памяти история; при положительном `N` — не больше `N` строк. Все десять полей — строки: `time_utc`, `mode`, `callsign`, `callsign_suffix`, `target`, `src`, `duration`, `loss`, `bit_error_rate`, `rssi`. Пустой массив — допустимый ответ. `/api/index.php` пуст. Остальные частые AJAX-запросы Dashboard в основном получают HTML-фрагменты или текст журнала; набора JSON-методов администрирования в клоне нет.

| Зависимость | Штатный Pi-Star | Наш Raspberry Pi OS Lite / Bookworm (`armhf`) |
|---|---|---|
| Веб-сервер | Выполняет PHP, устанавливает `DOCUMENT_ROOT`, передаёт `PHP_SELF`, защищает `/admin/` HTTP Basic Auth, обслуживает PHP-сессии, абсолютные URL, `admin/index.php → ../index.php` и ссылки на общие каталоги. Нужны системные утилиты; для ZIP — `zip`, PHP `ZipArchive` и `fileinfo`. | Статическая сборка Svelte не исполняет PHP. ## Чек-лист приёмки без рабочего узла

Это **план**, а не отчёт об успешном запуске. Для сверки достаточно исходников, обезличенных фикстур и сохранённых HTML/JSON. Для рендера PHP нужна изолированная одноразовая среда без радио, внешней сети, доступа к ФС хоста и настоящего `sudo`; вместо служб и внешних ответов — заглушки. Простое открытие страницы на узле не всегда безвредно: обычный GET `jitter_test.php` очищает журнал и запускает тест, некоторые редакторы создают временные файлы или начальный файл ключа.

- [ ] **Маршруты и граница доступа.** Сопоставить дерево файлов, цели символьных ссылок, меню, прямые URL, формы и AJAX-адреса с таблицами выше. На фикстурах публичного и административного экрана сравнить ссылки, баннеры и видимость контролов. Для предполагаемой конфигурации сервера проверить защиту всего `/admin/`, включая загрузки и вложенные редакторы, сохранение CSRF-полей/сессии и корректных `Content-Type`.
- [ ] **Выбор контроллера.** Подготовить три случая: только маркер MMDVMHost, только D-StarRepeater, ни одного. Ожидать соответствующие таблицы или сообщение с отложенным переходом. Отдельно сравнить один включённый и один выключенный `Network/Enable`: отключение POCSAG убирает страницы пейджера, отключение YSF не должно убирать историю DMR.
- [ ] **Радио и история.** На сохранённых логах RF и Net сверить время/часовой пояс, режим, адресата, текущую и законченную передачу, нулевой BER против отсутствующего, Loss против RSSI, фильтрацию Local TX, версии и статусы. Для D-Star — Rpt1/Rpt2, входящий/исходящий рефлектор, CCS и состав StarNet; для DAPNET — RIC, текст и Skyper. Проверить интервалы обновления по режимам.
- [ ] **Менеджеры сетей.** По HTML и заглушкам сравнить выбор модуля D-Star, слота BM/TGIF, рефлектора YSF, TG P25/NXDN и комнаты M17. Для TGIF проверить обе ветки (старый/новый выпуск, сеть, токен), пустой список, отказ API и отсутствие сети. Кнопки не должны подтверждать действие на основании одного факта отправки формы.
- [ ] **Configuration, Expert, Wi-Fi.** Сверить разделы Apply/Reset, исходные имена полей, редактор по ключам против полного текста, отдельные формы ключей, включённый/отсутствующий WLAN, вымышленные результаты сканирования. Проверить длинные списки, подписи, контраст индикаторов, русскую локализацию и компактную вёрстку, включая iframe и AJAX-фрагменты.
- [ ] **Обслуживание.** Для журнала — образцы до и после ротации, пустой файл, отсутствие доступа. Для загрузок — имя/тип и содержимое синтетического журнала/ZIP; для Backup/Restore — сверить список `backup_files()`. Калибровку, питание, сброс, Upgrade/Update, прошивку, SSH и jitter сверять по формам, подтверждениям и записанному выводу, без запуска обработчиков на системе.
- [ ] **Контракт и реализация.** Для PHP API сравнить все десять ключей и их типы, порядок записей, ограничения `N=0`, `N=1`, `N` больше истории, `[]`. Для Svelte отдельно подставить валидный массив, пустой массив, ошибку HTTP и не-JSON, проверить последние успешные данные и маркировку деморежима. Приёмка оформления, чтения данных и управляющей операции — три отдельных результата.
