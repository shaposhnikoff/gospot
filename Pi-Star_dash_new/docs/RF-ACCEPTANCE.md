# Полевой тест: входящий TG91/TС2 от BrandMeister

Это отдельная проверка внешней сети и эфира. Демо, зарегистрированный локальный peer или зелёный процесс DMRGateway не являются доказательством.

1. Выбрать одну Pi; записать её рабочие настройки и способ возврата к `dvserver`. Согласовать мастер BM, зарегистрированный ID хотспота с собственным суффиксом, пароль Hotspot Security. Пароль не помещать в журнал, скриншот или отчёт.
2. Проверить разрешённые маршруты DMRGateway: сетевой **TS2/TG91 → локальный TS2/TG91**, обычное групповое соединение. Номер TG совпадает с группой локального мастера, поэтому важно подтвердить, какая сеть используется.
3. После переключения увидеть успешную регистрацию на выбранном мастере **и на стороне BM**. Установить статическую подписку **91 / Slot 2** для именно этого хотспота в BrandMeister SelfCare; проверить список подписок. Для проверки входящего трафика не нужен тестовый PTT.
4. При известной активности сравнить время UTC и позывной в журнале BM, в журнале MMDVMHost и в Last Heard. Ожидается `Net`, `TG 91`, слот `2`. Фильтр «Сеть» оставляет вызов; «RF» скрывает его. Успешный вход, пустая TG и реальный входящий вызов — три разных результата.
5. Отдельно проверить звук на радиостанции (частота тестового узла, соответствующие TG, TS и Color Code). Запись на экране без слышимого звука подтверждает сетевой участок, но не весь тракт. Если за период наблюдения никто не говорил, записать **«нет образца»**, а не «неисправно».
6. По окончании снять временную подписку, вернуть конфигурацию и подтвердить повторный `session bound` на локальном сервере.
