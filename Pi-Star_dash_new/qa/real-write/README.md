# Сквозная запись без тестирования на рабочей Pi

Из `Pi-Star_dash_new` запустите **`qa/real-write/run.sh`**. Нужны Docker, Go, npm с локальными зависимостями, Chromium и совместимый ChromeDriver, Python 3, OpenSSL, socat и доступный `systemctl --user` на Linux. При первом запуске требуется доступ к пакетам Debian для контейнера тестового рантайма. Приложение тестируется в изолированной сети; Chromium подключается к нему через временный loopback-порт с проверкой TLS-ключа стенда.

В контейнере работают собранные из проекта интерфейс, Go-сервис и оба неизменённых Python-helper (перед запуском сравниваются SHA-256 скриптов). Права sudo взяты из установщика сервиса. Конфиги — копии файлов из `image/stage-mmdvm` с тестовыми идентификаторами и паролем. Тест сопоставляет действительное содержимое `/etc/*.ini` внутри контейнера с независимыми побайтовыми ожиданиями.

Для проверки готового релиза передайте `--dist build/release-hrs4N6/ui`: стенд скопирует ресурсы без сборки Vite и проверит SHA-256 `index.html` и файлов `assets/` внутри контейнера.

Для интерактивного превью: `qa/real-write/run.sh --preview`. Стенд остаётся запущенным до остановки процесса. Единственная точка входа — `http://127.0.0.1:8790/#console` (порт задаётся `PREVIEW_PORT`). Каталог, редакторы и API открываются на том же origin, в том числе после перенаправления порта приложением Codex. `8788` на рабочей машине не используется. Go-прокси принимает только loopback Host и same-origin записи, проверяет TLS-сертификат изолированного стенда и передаёт ему одноразовые тестовые учётные данные. Cookie превью отделена от защищённой cookie продукта; эта HTTP-оболочка не входит в релиз и не предназначена для рабочей платы. Данные конфигурации реальные на фикстуре, радио и эфир отсутствуют.

**Граница изоляции:** вместо системной шины рабочей машины контейнер получает один Unix-сокет. Адаптер допускает лишь перезапуск двух тестовых systemd-юнитов с одноразовыми именами. Однократный отказ генерирует сам процесс тестовой службы (`exit 42`); ответ о восстановлении требует подтверждения systemd (`ActiveState=active`, `ExecMainStatus=0`). Это проверка транзакций и реакции на отказ, а не эмуляция UART или процесса MMDVMHost. Вызовов SSH на Pi нет.

При выходе удаляются контейнер, изолированная сеть, временные учётные данные, ZIP и тестовые службы. Docker-образ тестового рантайма остаётся для повторных запусков.
