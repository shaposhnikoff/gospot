# Installing GoSpot

Russian version: [INSTALL.ru.md](INSTALL.ru.md) · Overview: [../README.md](../README.md)

There are two ways in:

1. **[Flash the GoSpot image](#1-flash-the-image)** — a complete Raspberry Pi OS
   Lite Trixie (Debian 13) armhf system with both packages already installed.
2. **[Install the two packages](#2-install-the-packages-on-an-existing-system)**
   on a Raspberry Pi OS you already run (Bookworm or Trixie), including an
   existing Pi-Star board.

Then work through the **[after-installation checklist](#3-after-installation)**.

Every path below is a setting in
[`Pi-Star_dash_new/gospot.conf`](../Pi-Star_dash_new/gospot.conf), installed on
the board as `/etc/gospot/gospot.conf`. If you changed a setting, use your
value, not the default printed here.

---

## 1. Flash the image

### Where the image file is

The image is built locally; see [`image/README.md`](../image/README.md) for the
build requirements and `./image/build.sh`. Each run creates a fresh directory
under `IMAGE_BUILD_PARENT` (default `/var/tmp`), outside the repository:

```
/var/tmp/gospot-image.XXXXXXXXXX/pi-gen/deploy/
├── image_<date>-gospot-trixie-armhf.img.xz           # the image
├── image_<date>-gospot-trixie-armhf.img.xz.sha256    # its checksum
└── image_<date>-gospot-trixie-armhf.manifest         # pi-gen commit, source commit, package versions
```

`gospot-trixie-armhf` is `IMAGE_NAME`; `<date>` is the build date that pi-gen
stamps in. Released images come with the same three files — check one before
flashing:

```sh
cd /var/tmp/gospot-image.*/pi-gen/deploy
sha256sum -c image_*-gospot-trixie-armhf.img.xz.sha256
```

Keep the `.manifest` and the `.sha256` with the image: the pinned commits fix
the build inputs, but the Raspberry Pi OS packages, kernel and firmware come
from the live archive, so two builds of the same sources are not identical.

### Writing it to the card

**Raspberry Pi Imager** — *Choose OS* → *Use custom*, pick the `.img.xz` file,
choose the card, write. Imager's customisation screen (hostname, user, Wi-Fi,
SSH key) works: the image keeps Raspberry Pi OS cloud-init. If you do not
customise anything, the image's own defaults apply.

**`dd`** — replace `/dev/sdX` with your card device and check it twice
(`lsblk`), because `dd` will not ask:

```sh
xz -dc image_<date>-gospot-trixie-armhf.img.xz \
  | sudo dd of=/dev/sdX bs=4M conv=fsync oflag=direct status=progress
sync
```

### First boot

Nothing secret is shared between boards flashed from one image. On the first
boot, before the management service starts:

- **SSH host keys** are generated by Raspberry Pi OS (the image carries none).
- **`gospot-firstboot.service`** (`/usr/local/sbin/gospot-firstboot`) removes
  anything in `/etc/gospot/wizard`, then generates this board's TLS private key
  and self-signed certificate (`CN=gospot`, with the host name and current
  addresses in the SAN) and sets the admin web password to the factory default.
  It writes `/var/lib/gospot-firstboot/done` last, so an interrupted first boot
  simply runs again next time.
- The dashboard services (`gospot-panel`, `gospot-wizard`, `gospot-stage`) and
  the daily host-file timer (`gospot-hostfiles.timer`) start. The **radio units
  stay disabled.**

Give it a minute or two, then:

| Where | Address | User | Password |
| --- | --- | --- | --- |
| SSH / console | `gospot.local` | `gospot` | `raspberry` |
| Operator panel | `http://gospot.local:8789/` | — | — |
| Wall display | `http://gospot.local:8789/kiosk` | — | — |
| Admin | `https://gospot.local:8788/manage/` | `gospot` | `raspberry` |

Use the board's IP address instead of `gospot.local` if mDNS does not resolve
on your network.

```sh
ssh gospot@gospot.local        # password: raspberry
```

The management certificate is self-signed, so the browser will warn. Compare
the fingerprint against the board before you trust it:

```sh
openssl x509 -in /etc/gospot/wizard/tls-cert.pem -noout -fingerprint -sha256
```

### Change the password first

Open **Configuration → Remote Access Password**, set a password and press *Set
Password*. One form changes both the admin web password and the password of the
`gospot` Linux account. The factory default `raspberry` is refused, as in
Pi-Star; the HTTPS service restarts a couple of seconds later, so the browser
will ask for the new credentials.

### Enable the radio services

Radio units are installed disabled on purpose — an unconfigured hotspot should
not transmit. Enable only the modes you use, after setting the callsign and
frequency:

```sh
sudo systemctl enable --now mmdvmhost.service     # the multi-mode controller
sudo systemctl enable --now dmrgateway.service    # DMR networks (BrandMeister, DMR+, ...)
sudo systemctl enable --now ysfgateway.service    # and p25gateway, nxdngateway, m17gateway, ...
systemctl status mmdvmhost.service
```

The Configuration page restarts the units it owns once they are enabled.

### Modem and UART

The image already prepares the GPIO serial port for a hat modem: `enable_uart=1`
in `/boot/firmware/config.txt`, no `console=serial0` in
`/boot/firmware/cmdline.txt`, and `serial-getty@ttyAMA0.service` and
`serial-getty@serial0.service` masked. Nothing to do for an MMDVM_HS or
ZUMspot hat beyond choosing the right **Radio/Modem Type** in Configuration,
which also sets the port (`/dev/ttyAMA0` for GPIO hats, `/dev/ttyUSB0` or
`/dev/ttyACM0` for USB modems). `sudo gospot-findmodem` reports what it finds.

## 2. Install the packages on an existing system

Raspberry Pi OS Bookworm or Trixie, armhf, Raspberry Pi 2 Model B or newer.
Copy both `.deb` files to the board and install them together, so `apt` resolves
their dependencies from the Raspberry Pi OS archive:

```sh
sudo apt update
sudo apt install ./gospot_0.2.0-1_armhf.deb ./gospot-radio_0.2.0-1_armhf.deb
```

Install them in one command: `gospot-radio` provides the layout that `gospot`
configures, and on a Pi-Star board a single transaction replaces both old
packages at once.

### What the packages create

**`gospot`** (dashboard):

- `/etc/gospot/gospot.conf` — the settings file, a dpkg conffile, so your edits
  survive upgrades. A package that adds new settings appends them to an edited
  copy and leaves your existing lines alone. After editing it by hand, restart
  `gospot-panel`, `gospot-wizard` and `gospot-stage`.
- `/usr/lib/gospot/` — the Go `panel` binary, the restricted helpers
  (`gospot-config`, `gospot-configure`, `gospot-power`, `gospot-native-update`,
  `gospot-modem`, `gospot-calibrate`, `gospot-jitter`) and the migration tools.
- `/usr/share/gospot/ui/` — the web interface.
- `/etc/sudoers.d/gospot` (mode 0440, validated with `visudo -c` at install
  time) — the exact helper invocations the services may run as root.
- `/lib/systemd/system/gospot-{panel,wizard,stage}.service`, enabled and
  started; the three unprivileged system accounts `gospot-panel`,
  `gospot-wizard` and `gospot-stage`.
- `/etc/gospot/wizard/` — this board's admin password plus the TLS key and
  self-signed certificate, generated at install time if they are missing.
- `/var/lib/gospot` and `/var/lib/gospot-bm` — helper state and the
  BrandMeister cache.

**On a fresh install the admin password is random**, not `raspberry`. Read it
once and change it from Configuration:

```sh
sudo cat /etc/gospot/wizard/admin-password
```

**`gospot-radio`** (radio services):

- The radio binaries in `/usr/local/bin` (MMDVMHost, DMRGateway, the
  YSF/P25/NXDN/M17/DAPNET/DGId/APRS gateways, the cross-mode bridges, the
  parrots, MMDVMCal, MobileGPS, the D-Star daemons) and the `gospot-*` tools and
  service handlers in `/usr/local/sbin`.
- The shared libraries Debian does not carry (`libwiringPi`,
  `libArduiPi_OLED`) in `/usr/local/lib`, registered with `ldconfig`.
- The `mmdvm` system account (groups `dialout` and `tty`),
  `/var/log/gospot` (`root:mmdvm`, mode 0775) and `/usr/local/etc` for the host
  lists and ID databases.
- A systemd unit per service in `/lib/systemd/system`, **all disabled**, and
  `gospot-hostfiles.timer`, enabled: ten minutes after boot and then daily
  (with a random delay of up to two hours) it refreshes the host lists, the
  talkgroup lists and `DMRIds.dat`.
- `/etc/gospot-release` if it does not exist yet. Missing radio
  configurations are seeded from the Pi-Star defaults rewritten for the GoSpot
  layout; **existing configuration files are never touched.**

### Migrating an existing Pi-Star board

The packages declare `Conflicts`/`Replaces`/`Provides` on `pistar-dashboard`
and `pistar-radio`, so `apt` removes the old packages and installs these in
their place. The migration then runs by itself, from the `postinst` scripts:

- **Settings** — `/etc/pistar-dashboard/pistar.conf` becomes
  `/etc/gospot/gospot.conf`: the new packaged file, with your values for every
  key that still exists (`PISTAR_*` → `GOSPOT_*`). A value that matched the old
  packaged default takes the new default; build-time settings (install paths,
  ports, unit names) always take the new default.
- **Credentials and state** — the admin password, the TLS key and certificate,
  the helper state directory and the BrandMeister cache are copied with their
  modes and times; files owned by the old service accounts move to the new
  ones. The API key files change owner. The old `pistar-panel`,
  `pistar-wizard` and `psdash-stage` units are stopped and disabled so the
  GoSpot services can take their ports.
- **Logs** — `/var/log/pi-star/*` moves to `/var/log/gospot` (the files
  themselves are moved, no symlink), and **the log paths inside the radio
  configurations are rewritten** to match. If logs or configurations moved, the
  active radio units are restarted, because a running daemon would keep writing
  to the old path.
- **Other files** — `/etc/pistar-release` → `/etc/gospot-release`
  (`[Pi-Star]` → `[GoSpot]`), `/etc/pistar-css.ini` → `/etc/gospot-css.ini`,
  `/etc/pistar-remote` → `/etc/gospot-remote`, the Keeper logbook, the MOTD
  generator, and the Wi-Fi country modprobe file.
- **Unit enablement** — an enabled `pistar-watchdog`, `pistar-remote` or
  `pistar-hostfiles` unit results in the matching `gospot-*` unit being
  enabled; a running one is stopped and its GoSpot counterpart started.

**Your admin login becomes `gospot`, with the password you already used.** The
old `pi-star` name is gone; the password is unchanged.

Both migrations are idempotent and **delete nothing**: an old file whose new
location already exists stays where it is and is reported in the install log. A
marker in `/var/lib/gospot` makes later runs a no-op, so your edits to the new
settings file are never overwritten. Read the install output, or
`journalctl -u gospot-panel -u gospot-wizard`, if anything looks off.

### Modem and UART on an existing system

If your modem is a GPIO hat and the board was not already running Pi-Star, free
the serial port yourself — the packages do not edit the boot files:

```sh
# drop the serial console from the kernel command line
sudo sed -i -E 's/(^| )console=(serial0|ttyAMA0|ttyS0)(,[^ ]*)?( |$)/\1/g' /boot/firmware/cmdline.txt
# enable the GPIO UART
grep -q '^enable_uart=1' /boot/firmware/config.txt \
  || printf '\n[all]\nenable_uart=1\n' | sudo tee -a /boot/firmware/config.txt
sudo systemctl mask serial-getty@ttyAMA0.service serial-getty@serial0.service
sudo reboot
```

On Bookworm and older layouts the two boot files may be `/boot/cmdline.txt` and
`/boot/config.txt`. USB modems (`/dev/ttyUSB0`, `/dev/ttyACM0`) need none of
this.

## 3. After installation

Open **`https://<board>:8788/manage/`** and work down the list. Each section
writes its files and restarts the services it owns when you press *Apply*.

1. **Password** — Configuration → *Remote Access Password*, if you have not
   changed it yet.
2. **Callsign and ID** — Configuration → *General Configuration*: *Node
   Callsign* and *CCS7/DMR ID*. Nothing talks to a network without them.
3. **Frequency** — same section: *Radio Frequency* (or *Radio Frequency RX* and
   *TX* in duplex). Use a frequency you are licensed for.
4. **Modem** — same section: *Radio/Modem Type*. This sets the modem port and
   speed. `sudo gospot-findmodem` helps if you are not sure what is attached.
5. **Modes** — Configuration → *Control Software*: the controller
   (MMDVMHost or DStarRepeater), simplex or duplex, and the switches for DMR,
   D-Star, YSF, P25, NXDN, M17 and POCSAG.
6. **DMR master** — Configuration → *DMR Configuration*: *DMR Master*
   (BrandMeister, DMR+, XLX, FreeDMR, …), *DMR ESSID* and *DMR Color Code*. For
   BrandMeister talkgroup management add the API key in Expert → *API Keys*.
7. **Enable the services** for the modes you switched on (see
   [above](#enable-the-radio-services)), then watch
   **Live Logs** and the operator panel: the master should come up and the modem
   should report itself.
8. **Back it up** — Backup/Restore writes a ZIP of the configuration: the
   radio configs, the controller markers, the API keys, the CSS file,
   `RSSI.dat`, `hosts`/`hostname` and `wpa_supplicant.conf`. System passwords
   are not in it.

Calibration, the CSS Tool, the jitter test and the wall display at
`/kiosk` are there whenever you want them.
