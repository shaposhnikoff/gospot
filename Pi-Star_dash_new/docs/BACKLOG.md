### REPO-01

Переезд в <https://github.com/shaposhnikoff/gospot-radio> чистым стартом.
Решения пользователя записаны в [AGENTS.md](../AGENTS.md).

Порядок работ:

1. Довести образ Trixie до зелёного и слить ветку в текущем репозитории.
2. Собрать новое дерево: `dashboard/` (бывший `Pi-Star_dash_new`), `panel/`,
   `radio/`, `image/`, `docs/`, `.github/`. Без `compat/`, `qa/classic-*`,
   `docs/configure-spec`, `docs/PARITY.md`, `tasks/` и кода миграции с
   пакетов `pistar-*`.
3. Перевести сборку радиочасти на исходники g4klx: закреплённые ревизии
   MMDVMHost, DMRGateway, YSFClients, P25Clients, NXDNClients, M17Gateway,
   DAPNETGateway, MMDVMCal и прочего, сборка в контейнере целевого выпуска,
   как `radio/build-dstar.sh`. Таблица переименования и готовые бинарники
   Pi-Star больше не нужны. Списки хостов по-прежнему скачиваются с pistar.uk.
4. Документация на двух языках, релизы с пакетами, образом и суммами.
5. Один первый коммит, затем проверка целиком: юнит-тесты, стенд, пакеты,
   образ, установка на плату.

**Приёмка:** в новом репозитории `grep -ri "pistar\|pi-star"` находит только
адреса pistar.uk и подпись «Pi-Star compatible»; все наборы тестов зелёные;
пакеты и образ собираются из чистого клона.

### CLI-01

Интерфейс командной строки `gospot` с тем же набором действий, что и у веба
(решение пользователя 2026-11-27: полный набор, обычные подкоманды, без TUI).
Чтение идёт из файлов и локального API без прав, запись — через те же
root-помощники, что и дашборд, поэтому проверки, ревизии, порядок перезапуска
служб и откаты общие. Пароли и ключи только из stdin или по запросу, никогда
в аргументах. У каждой команды `--json`.

| Группа | Команды |
|---|---|
| Состояние | `status`, `heard [-n] [-f]`, `log <служба> [-f]`, `links`, `doctor` |
| Настройка | `config show/set`, `expert get/set/edit`, `css set`, `keys set` |
| Радио | `service list/start/stop/restart`, `link`, `unlink`, `bm static`, `tgif static`, `calibrate`, `jitter` |
| Эксплуатация | `backup`, `restore`, `update`, `power`, `wifi`, `factory-reset` |
| Прочее | `version`, `completion bash|zsh`, `api <путь>`, `hoseline <TG>` в stdout |

`doctor` — одна команда для разбора неисправности: отвечает ли модем, есть ли
сеть и DNS, вошёл ли DMR на мастер, свежесть списков хостов, место на диске,
часы, ошибки в журналах за сутки.

**Открытые вопросы:** брать ли `hoseline` и `doctor` в первую версию; нужен ли
доступ без `sudo` для членов отдельной группы.

**Приёмка:** юнит-тесты на разбор аргументов и на каждую команду записи против
фикстур; на стенде `qa/real-write` прогон, где CLI и страница меняют один и тот
же параметр и дают одинаковый результат; проверка, что секреты не попадают в
аргументы и в журналы.

### CFG-01

В **Configuration → MMDVMHost** оператор отмечает используемые протоколы.
Выбор сразу открывает поля соответствующего протокола, снятие выбора скрывает
их. До нажатия «Сохранить» файл и службы не меняются. Набор режимов берётся
из возможностей установленного MMDVMHost и конфигурации узла; параметры
выключенного режима сохраняются для следующего включения.

**Приёмка:** в Chromium на настольном и мобильном экранах включить на стенде
YSF при уже включённом DMR, изменить параметр YSF, сохранить и заново открыть
Configuration через меню. Независимо сверить `/etc/MMDVM-Host.ini`, включая
RF- и Network-секции, права файла и неизменность DMR. Отдельно проверить
отключение YSF и отсутствие записи при уходе со страницы без сохранения.

### BM-01

В меню нужна отдельная страница **BrandMeister**, также доступная из
конфигуратора DMR. На ней оператор видит ID текущего пира, выбирает мастер
по ID, стране или адресу и находит нужную TG по номеру или названию.

| Справочник | Источник |
|---|---|
| Мастера | <https://api.brandmeister.network/v2/master> |
| Разговорные группы | <https://api.brandmeister.network/v2/talkgroup> |

- Сохранение мастера меняет настройки DMRGateway на узле. **«Добавить группу
  пиру»** создаёт статическую подписку в сети BrandMeister для выбранного
  пира и слота. Изменение локального `TGRewrite` эту операцию не заменяет.
- Показывать текущие подписки; разрешить добавить TG и удалить выбранную
  подписку, не затрагивая другие группы и слоты. Для симплексного пира
  использовать слот `0`, для дуплексного — выбранный `1` или `2`.
- Для чтения публичных справочников ключ не нужен. Для изменения подписок
  предусмотреть ввод **BM API key** в HTTPS-админке. Это не пароль Hotspot
  Security. Не возвращать сохранённый ключ браузеру и не выводить его в
  журналы, репозиторий или тестовые протоколы. Реальный ключ понадобится
  только при согласованной проверке на реальном пире; для стенда — тестовый.

**Приёмка:** на локальном HTTPS API выбрать TG из справочника, добавить её
пиру, перечитать профиль, удалить ту же подписку и снова перечитать профиль.
Для каждого действия сверить CSRF, ID пира, слот, TG и ровно один
авторизованный запрос. Обновление страницы не должно повторять команду.
Проверить отказ при отсутствии/неверном ключе и HTTP 503: оператор видит
причину ошибки, ложного сообщения об успехе нет, подписки не изменены.
