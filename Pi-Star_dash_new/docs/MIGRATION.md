# Переезд с Pi-Star_DV_Dash на Svelte и Go

Источник требований: клон `Pi-Star_DV_Dash` ревизии `10bf34c9`. Полный перечень маршрутов, режимов, зависимостей и проверок — в [PARITY.md](PARITY.md). Перенос считается выполненным для **операции**, а не для ссылки или страницы с новым оформлением.

## Архитектура

- **Демонстрация** на машине разработки: синтетические ответы, переключение ошибок, проверка всех состояний без передачи в эфир.
- **Raspbian / MMDVM** на `pistar3`: отдельная панель `:8789`, статический Svelte и запросы на своём origin к `/api/status`; источники — `journald`, INI и текущие запуски systemd. Мутации выносятся на HTTPS `:8788` и разрешаются только через типизированный локальный helper. Старую панель `:8787` оставляем доступной при пилоте.
- **Штатный Pi-Star**: полный исходный PHP docroot с темой и прежними маршрутами, AJAX, Basic auth, CSRF и относительными ссылками. Это мост для поэтапного переезда, **не** реализация функций в Go. Для соответствующего режима требуется реальный сервер Pi-Star со своими службами и правилами web-сервера; запускать каталог PHP как статические файлы нельзя.

## Очередь переноса

| Этап | Что переносим и откуда | Условие приёмки |
|---|---|---|
| 1. Обзор, DMR Last Heard, локальный RF | `index.php`, `mmdvmhost/{repeaterinfo,lh,localtx}.php`, `api/last_heard.php` | На Pi показаны её позывной и актуальные свидетельства; фильтр RF/Net, время, пустой журнал и недоступный источник различимы. Отсутствующая метрика не заменяется нулём. |
| 2. Конфигурация DMR-узла | Подмножество `admin/configure.php`: позывной, частота, UART, локальный ID и claim мастера. Импорт и экспорт публичных полей отдельно от полного резервного архива. | Сверка GET со штатным INI без вывода пароля, контролируемый POST с CSRF, проверка отката на копиях. На Pi сначала проверяется вход и чтение; изменение частоты и реальный откат требуют окна обслуживания. |
| 3. Диагностика и архивы | `admin/{sysinfo,live_modem_log,download_modem_log,config_backup}.php` | Эквивалентные системные показатели и журнал с ограничением размера. Для резервной копии — полный перечень форматов, разрешённые пути, проверяемый импорт ZIP и откат в изолированном окружении. |
| 4. Протокольные функции | `mmdvmhost/*_manager.php`, `dstarrepeater/`, POCSAG, BM/TGIF, шлюзы D-Star/YSF/P25/NXDN/M17 | Для каждого режима — модель необходимых служб, адаптер, позитивный сценарий, отказ сети и тест с соответствующим оборудованием. Отсутствие службы не маскируется подключённой кнопкой. |
| 5. Системное администрирование | `admin/{wifi,power,update,calibration}.php`, `admin/expert/` | Отдельные ограниченные API вместо произвольного выполнения shell. Тестовые адаптеры для Wi-Fi и обновлений; тестовая плата и физический доступ для прошивки и восстановления. |
| 6. Переключение | По одной функции: PHP → Svelte/API, затем следующий модуль | Таблица соответствия маршрутов и операций, мобильные/настольные проверки, испытание на целевой плате, сохранённый способ вернуться. Старый путь удаляем только после подтверждения эквивалентности. |

В таблице перечислены **критерии**, а не утверждения о пройденных испытаниях. В частности, CSS-покрытие всех PHP-страниц, синтаксические тесты PHP и успешный HTTP 200 не подтверждают калибровку, обновление прошивки, восстановление архива или прохождение звука через эфир.
